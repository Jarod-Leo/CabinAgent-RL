# 06 统一评测与报告阶段

## 状态

未开始，等待阶段 05 产生有效 checkpoints。

## 目标

- 用统一协议选择 checkpoint，并评估工具调用、长程交互、安全边界和泛化能力。
- 形成可审计的主结果、消融表、失败分析和系统效率报告。

## 固定设置

| 数据 | 用途 | 规则 |
|---|---|---|
| CAR train | RL task pool | 不用于最终结果 |
| CAR dev 26 task | 每 50 step checkpoint 评测与选择 | 不参与梯度更新 |
| CAR test 125 task | 最终冻结评测 | 模型选择完成后只运行一次 |
| BFCL V4 fixed subset | 工具格式与泛化评测 | 所有模型使用同一 manifest |

主要指标：CAR success、consistent pass、final-state correctness、tool/argument accuracy、parse/executable rate、invalid/redundant calls、turn/token p50/p95、loop、recovery、hallucination、limit awareness、disambiguation、policy violation，以及 simulator latency/throughput、trainer wait、GPU memory 和 step time。

## 执行结果

- 当前只有 baseline 和 rollout gate 指标。
- 尚无 E10-E14 或 F10-F14 checkpoint，因此不能生成正式消融比较或最终 CAR test 结论。
- G00/G01/G02 是训练可行性 gate，不应当被当作训练后 benchmark 结果。

## 已完成改进

- 已建立统一 trajectory schema、failure taxonomy、report builder 和 BFCL/CAR adapter。
- 已冻结 checkpoint 评测点为 50/100/150/200/250。
- 已规定保存所有 attempt 与逐 checkpoint 结果，防止只报告最佳值。

## 遗留问题与下一步

1. 等待阶段 05 至少产出一个有效训练家族。
2. 在 CAR dev 和 BFCL 上完成同配置 checkpoint 选择。
3. 冻结选择后执行一次 CAR test。
4. 汇总均值、方差、失败类型、资源消耗和相对 Vanilla 的增益。
5. 对计划中的主张执行 result-to-claim 检查，再决定是否补充消融。

- 五组消融对比表
- CAR test 与 BFCL 最终报告
