# 01 基础与数据准备阶段

## 状态

已完成。

## 目标

- 建立可本地运行、无需 GPU 的 baseline 和统一 trajectory/report 接口。
- 下载并验证完整 CAR-bench 与 BFCL V4 数据。
- 将集群项目迁移到用户指定的 SSD 根目录。

## 设置

| 项目 | 设置 |
|---|---|
| 本地 policy | deterministic `local_rules` adapter，仅用于开发 smoke |
| 正式 policy | `Qwen/Qwen2.5-7B-Instruct` |
| 数据根目录 | `/projects/jiatian001ssd/cabinagentrl/CabinAgent-RL/data/official` |
| CAR 数据 | 官方 GitHub 代码与 Hugging Face 完整 snapshot |
| BFCL 数据 | Gorilla 仓库中的 BFCL V4 数据 |
| 存储 | `jiatian001ssd` 项目 SSD，配额 150 GB |

## 执行结果

- 本地 baseline、数据构建、PRM-Lite 和报告链路均可运行。
- 30 分钟 Slurm smoke `129967` 完成，运行 `30:02`，退出码 `0:0`。
- CAR 完整 snapshot：18 个文件、`720,638,694` bytes、254 条 task、10 个 mock-data JSONL。
- BFCL V4：51 个 JSON/JSONL 文件，共解析 9,673 条记录。
- SSD 迁移作业 `130531/130532/130535` 完成；文件计数、字节数和 checksum 一致，旧路径已移除。

## 已完成改进

- 为 standalone Python 脚本补齐仓库根目录导入路径。
- 对 CAR/BFCL 使用结构化解析，兼容 JSON 与 JSONL。
- 迁移过程采用复制、checksum、功能验证、最终切换的保护流程。
- 明确 sample 数据只能用于 smoke，不能被表述为官方评测结果。

## 遗留问题与下一步

- 完整数据只用于后续固定 split 和冻结评测，不把隐藏 ground truth 暴露给 policy。
