### HDD 冷归档目录创建 / 2026-09-04

#### 实验设置

- 实时 `storagemgr` 核对用户配额为 SSD `150 GB`、HDD `250 GB`；按已确认的冷热分层方案创建一个长期 HDD 项目目录，容量使用全部 HDD 配额，项目软使用上限由项目脚本控制为 `180 GB`。
- 原计划名为 `cabinagentrl-archive`；storage manager 只接受安全的字母数字名称，因此使用等价永久名 `cabinagentrlarchive`，路径 `/projects/cabinagentrlarchive`。

#### 执行结果

- HDD 目录创建成功，实时配额显示 `0 B used / 250.0 GB assigned`；SSD 同时为 `148.8/150.0 GB`。
- 本操作只创建目标目录，没有复制、移动或删除 SSD 文件。

#### 改进原因

- step 100 保存后 step 50/100 两份完整 checkpoint 同时存在，合计约 `62.89 GB`，证明 150 GB SSD 无法同时承担长期模型、环境、缓存和多 checkpoint 历史。
- 不可变大模型只在作业启动时读取，适合经过计算节点加载 smoke 后直接从 HDD 使用；活动 checkpoint、环境、缓存、数据和实时日志仍需 SSD。

#### 改进措施

- 冷数据采用显式 archive manifest，不建立透明软链接；复制必须通过 Slurm，先验证 exact file set/size/SHA-256，再允许删除 SSD 源。
- HDD 设 `180 GB` 项目软上限，全项目最多 3 个完整 checkpoint；当前 active、F10 baseline best 和 challenger best 各占一个槽位。
